# FlowCast 音频分享大改设计

- 日期：2026-08-08
- 状态：设计已确认，用户已明确免除书面审阅
- 交付方式：一个版本完成，对内按模块隔离实现

## 1. 背景

FlowCast 已经具备 Windows 程序音频路由、Voicemeeter Banana B1 控制、分享历史、托盘、更新与安装包基础，但现有主窗口同时承担界面、路由、恢复、健康检查与更新流程，导致状态容易互相覆盖。过去出现过以下用户可见问题：

- 没有实际分享却显示“正在分享”，或已经分享却显示 B1 关闭。
- 开始、停止、切换程序后，程序没有可靠恢复到分享前的播放路径。
- 程序结束、设备消失或 FlowCast 异常退出后，路由状态残留。
- 同时勾选多个程序、重复点击开始或控件未锁定，造成状态竞争。
- 原始设备名称过长，撑宽程序卡片与主界面。
- 更新完成后仍启动旧版本，失败时缺少可靠回滚。
- 技术错误直接暴露给用户，无法明确知道影响与处理方法。

本次大改保留已经验证过的 WPF、Windows 路由执行器和 `router-helper`，重写上层控制流程与主界面，不迁移到 WinUI，也不重写底层音频引擎。

## 2. 目标

1. 任一时刻最多分享一个程序，并消除重复开始、重复停止和切换竞争。
2. 所有“正在分享”“已停止”状态必须来自真实 Windows 路由和 Banana B1，而不是来自复选框或按钮文字。
3. 停止分享、切换程序、程序结束、设备丢失或退出 FlowCast 时，恢复分享前的播放路径。
4. 当恢复暂时无法完成时，先停止朋友端音频，再记录待恢复任务；不能阻止用户关闭 FlowCast。
5. 把主界面改为紧凑、清晰的 Apple 浅色玻璃风格，长设备名称不得改变卡片宽度。
6. 提供白话的检查与一键修复，不把堆栈、协议错误或设备 ID 直接显示给普通用户。
7. 更新过程可验证、可回滚，并保证重启的是新版本。
8. 最小化后停止非必要动画和高频界面刷新，同时继续执行分享安全监控。

## 3. 非目标

本次不实现以下内容：

- FlowCast Lyrics、歌词接收器或 Radmin VPN 功能。
- 设备隐藏、驱动删除或设备管理功能。
- 房间、邀请码、听众、播放列表、反应、心情标签等社交功能。
- 全局快捷键、Discord 运行检测、诊断页面或诊断导出。
- 程序音量、分享音量或独立音量控制。
- 倒数计时停止分享。界面只保留正常的累计分享时长。
- 暂停分享状态。静音分享不会暂停或重置分享时长。
- 同时分享多个程序。
- 自动发布 GitHub Release。本次只完成本机可验证代码与本机打包。

## 4. 核心交互规则

### 4.1 单一程序选择

- 程序列表使用单选语义，一次只能选一个程序。
- 不再提供独立的“开始分享”按钮。点击未选程序的圆形选择控件后，打开 FlowCast 自定义确认窗；确认后才开始分享。
- 没有播放声音的程序仍可选择和开始分享。无信号只显示为提示，不是开始条件。
- 正在分享的程序不能取消选择，也不能修改播放路径。用户必须点击“停止分享”，或选择另一个程序执行切换。
- 分享期间点击另一个程序时，显示确认：是否停止当前程序、恢复其原路径，并改为分享新程序。
- 用户取消确认时，不改变任何勾选、路径、B1 或分享状态。
- 切换成功前，旧程序仍是当前程序；只有旧路由安全停止并完成必要恢复后，才提交新选择。

### 4.2 程序路径

- 未选程序可以在 FlowCast 内修改播放路径。
- 路径选择器只显示普通播放设备与“跟随 Windows 默认播放设备”。FlowCast 内部分享端点不作为用户可选项目显示。
- 设备名称过长时以省略号截断；悬停或展开详情可查看完整名称，但不得撑宽卡片。
- 多个端点同时被 Windows 报告时，主列表只显示“多个播放设备”，不拼接所有端点名称。
- 被选程序进入分享后，路径位置改为只读的“正在分享”，不显示可能误导的原设备下拉框。
- 开始分享时，被选程序送到 FlowCast 分享端点；其他当前检测到的可路由程序统一送到仅本机 AUX。分享期间新出现的可路由程序也必须送到 AUX，保证没有选中的程序不会进入 B1。
- FlowCast 必须为所有被临时修改的程序保存原路径；停止、切换或退出时一并恢复，不能只恢复被选程序。
- 停止后恢复分享前记录的端点 ID；如果该设备已不存在，则恢复到当前 Windows 默认播放设备，并明确告知用户发生了回退。

### 4.3 停止、静音与退出

- “停止分享”按一次后立即进入恢复中并禁用，避免重复执行。
- 停止顺序为：关闭朋友端分享通道、恢复程序路径、验证结果、清除选择、写入历史。
- “静音分享”只让朋友暂时听不到，不改变程序路径、不清除选择、不停止累计时长。
- 关闭主窗口时显示 FlowCast 自定义选择窗：“最小化到托盘”或“退出 FlowCast”。
- 选择退出时执行恢复；恢复失败或超时也不能卡住关闭。待恢复信息保留到下次启动继续处理。
- Windows UAC 是唯一允许保留的系统原生窗口，其他确认、错误、历史、设置、更新和关闭窗口全部使用 FlowCast 自定义窗口。

## 5. 真实状态模型

`ShareCoordinator` 是唯一允许改变分享状态的入口。界面不得直接写 B1、路由或选择状态。

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| `LocalOnly` | 没有程序分享，声音只在本机播放 | 选择程序、修改未选程序路径 |
| `Preparing` | 已确认程序，正在保存原路径并建立分享路由 | 取消不可用，等待完成或自动回滚 |
| `Sharing` | 程序路由与 B1 均经真实读取确认 | 静音、停止、切换程序 |
| `Muted` | 路由保持，朋友端暂时静音 | 取消静音、停止、切换程序 |
| `Restoring` | 正在关闭 B1 并恢复原路径 | 其他路由操作禁用 |
| `AttentionRequired` | 期望状态与真实路由不一致 | 一键修复、停止、退出 |

状态判定至少包含以下事实：

- 当前选中程序仍存在，或存在可识别的应用路由规则。
- 当前程序实际输出端点是否为 FlowCast 分享端点。
- Banana B1 的实际开关状态。
- 必需的 Input、AUX 与 `router-helper` 是否可用。
- 路由更改后的再次读取是否与目标一致。

没有选中程序时，B1 关闭或无法读取不显示为主界面错误，也不阻止退出。FlowCast 只在用户准备分享或正在分享时要求 B1 满足条件。

## 6. 模块边界

### 6.1 `ShareCoordinator`

负责状态机、单程序选择、开始、停止、静音、切换和异常恢复。所有命令串行执行，并使用操作代号忽略过期结果，防止快速点击或刷新回调覆盖新状态。

依赖：`RouteTruthService`、`RouteExecutionService`、`RecoveryJournal`、`ShareHistoryStore`。

### 6.2 `RouteTruthService`

把现有 `ApplicationRouteVerifier`、Banana B1 读取、端点检测和程序存活信息合并为一次不可变快照。界面状态只消费快照，不自行推测。

它负责区分：

- 仅本机播放。
- 分享路由已经建立但 B1 未开启。
- B1 已开启但程序仍走原设备。
- 分享完整生效。
- 程序无音频信号但路由有效。

### 6.3 `RouteExecutionService`

封装现有 `RouteCoordinator`、`ApplicationRouteExecutor`、`VoicemeeterSharingBusService` 与 `router-helper`。它只执行明确命令，并在每次变更后交给 `RouteTruthService` 验证，不负责 UI 状态。

### 6.4 `RecoveryJournal`

在第一次修改路由前，以原子写入保存：应用身份、程序显示名、原端点 ID、目标分享端点、操作阶段、开始时间与最后一次验证结果。不得保存任何音频内容。

- 正常恢复并验证成功后删除记录。
- 程序消失、FlowCast 崩溃或电脑关机造成未完成恢复时，下次启动先关闭 B1，再尝试按应用身份恢复。
- 如果无活动音频会话导致暂时无法恢复，则保留待恢复记录；同一应用再次出现时先恢复，再允许新的分享。
- 恢复日志不得让 FlowCast 无法退出。

### 6.5 `RepairCoordinator`

为“需要处理”状态生成一个主要动作，不显示技术细节：

- Banana 已安装但未运行：启动并最小化 Banana。
- Input 或 AUX 暂时未发现：重新读取设备并刷新音频服务状态。
- 程序路径错误：重新应用分享路径并验证。
- B1 错误：仅在有当前分享程序时修复 B1。
- `router-helper` 不可用：验证打包清单并重启帮助程序。

Voicemod 是可选组件。FlowCast 启动时可以静默尝试打开，但不显示“未安装”或健康卡片，也不把它作为分享条件。

### 6.6 `UpdateTransaction`

把下载、校验、备份、替换、重启和回滚视为一笔事务。旧版本只有在新包完整验证后才退出；替换程序在安装目录外运行，避免文件锁定。

### 6.7 界面层

把现有 `MainWindow.xaml.cs` 的职责拆到主窗口 ViewModel、程序列表 ViewModel、状态摘要 ViewModel 与独立对话框。代码后台只保留窗口生命周期和必须的 WPF 事件桥接，不直接执行路由。

## 7. 关键流程

### 7.1 启动

1. 单实例锁成功后显示 3 秒 FlowCast 开屏；第二次启动只唤醒现有窗口。
2. 开屏使用实时绘制的声波、音符与传送线条，不使用带白底的静态中央 Logo 图片。
3. 动画末尾 Logo 必须清晰，播放一次短促电子提示音；声音只送到已确认的本机监听设备。如果当前默认设备解析为 FlowCast 分享端点，则不播放提示音。
4. 主窗口在开屏结束前保持隐藏，避免瞬间闪出主画面。
5. 尝试启动并最小化已安装的 Banana；静默尝试启动 Voicemod。
6. 读取未完成恢复记录，先关闭残留朋友端分享，再恢复应用路径。
7. 检查 Banana、Input、AUX、B1、默认播放设备与 `router-helper`，生成初始真实状态。

### 7.2 开始分享

1. 用户选择一个程序并确认。
2. `ShareCoordinator` 建立操作代号，锁定相关控件。
3. 保存原路径与恢复日志。
4. 把被选程序应用到 FlowCast 分享端点，并把其他可路由程序应用到仅本机 AUX。
5. 打开 B1。
6. 重新读取程序路径与 B1。
7. 两者都正确才进入 `Sharing`；无声音信号仍可成功。
8. 任一步失败时先关闭 B1、恢复原路径，再显示白话错误。

### 7.3 切换程序

1. 用户点击另一个程序并确认切换。
2. 旧程序进入 `Restoring`，先停止朋友端声音并恢复旧路径。
3. 旧程序恢复达到安全状态后，才清除旧选择并开始新程序的分享流程。
4. 新程序启动失败时保持 `LocalOnly`，不能自动重新分享旧程序。

### 7.4 自动恢复

以下事件触发安全停止：

- 当前程序确认结束。程序仍存活时，短暂无声或音频会话重建不触发停止。
- 当前输出设备被拔除或禁用。
- Windows 在分享期间把程序改到其他端点。
- Banana、B1 或 `router-helper` 丢失。
- FlowCast 正常退出。

安全停止先保证朋友端听不到，再恢复本机路径。若恢复需要等待应用再次出现，主界面显示“已停止分享，等待恢复该程序的本机播放路径”，但不把它显示为仍在分享。

## 8. 界面设计

### 8.1 主窗口

- 采用固定合理范围的窗口尺寸，不允许内容把窗口无限横向拉长。
- 顶部只保留品牌、设置、教程、历史和刷新。
- 第一张状态卡显示真实分享状态、当前程序、累计时长、输入信号提示与静音/停止动作。
- 第二张卡显示程序列表；系统状态默认收合为一行“系统已就绪”或“需要处理”。
- 程序列表独立滚动，每行保持统一高度。长名称、PID 和路径摘要在固定区域截断。
- 分享程序显示醒目的鲜蓝单选标记和“正在分享”，未选程序显示路径选择器。
- 底部不再放“开始分享”按钮，也不保留倒数计时按钮。

### 8.2 自定义窗口

所有窗口共享 FlowCast 字体、圆角、阴影和颜色变量，但按用途区分视觉层级：

- 确认窗口：简洁中性，主要与取消动作清楚分开。
- 错误/修复窗口：浅暖色提示区，突出唯一建议动作。
- 历史窗口：可上下滚动，显示应用、开始、停止、时长与停止原因。
- 更新窗口：独立进度、当前阶段与不可重复点击状态。
- 关闭窗口：只提供最小化到托盘与退出两个选择。

### 8.3 动画与性能

- 只在启动、状态切换、列表增减、确认成功和错误出现时播放动画。
- 点击反馈使用短促缩放与亮度变化，不使用持续扫光、多个光圈或无限循环波纹。
- 前台动画目标为 60 FPS，但不得用持续高频计时器强制刷新静止画面。
- 最小化或进入托盘后停止气氛条、装饰声波、列表过渡和非必要 UI 轮询。
- 最小化后保留低频真实路由监控、程序退出监控、恢复任务与更新替换流程。

## 9. 白话错误规则

每个错误只显示三件事：

1. 发生了什么。
2. 对当前分享有什么影响。
3. 用户现在可以按什么。

示例：

- “Chrome 仍在通过显示器播放，所以朋友还听不到。点击‘重新连接’后，FlowCast 会再次设置分享路径。”
- “Voicemeeter 暂时没有回应。分享已经停止，你的程序声音会恢复到本机。点击‘重新打开’再试一次。”
- “原来的耳机已不在电脑上。FlowCast 已改用 Windows 默认设备，朋友已听不到该程序。”

技术代码、设备 ID、协议输出与堆栈只写入本地技术日志，不出现在普通提示。技术日志不包含音频内容。

## 10. 分享历史与本地数据

- 历史记录保存程序名称、开始时间、停止时间、持续时长与停止原因。
- 主界面累计时长与历史窗口都从已完成记录加当前活动会话计算。
- 静音不会切断记录，也不会重置时长。
- 历史窗口支持滚动，记录数量超过显示范围时不扩大窗口。
- 偏好只保存窗口位置、关闭行为、教程完成状态、可选开屏音效与隐藏程序清单。
- 不记住 Chrome、网易云等程序的偏好播放路径，也不自动套用历史路径。
- 不保存、录制、分析或上传音频内容。

## 11. 更新事务

1. 只有检测到更高版本时才显示更新入口。
2. 用户确认后打开自定义进度窗，显示下载、校验、准备替换、重启四个阶段。
3. 下载包必须通过 SHA-256 与包结构验证；安装产物仍以单一 Setup EXE 交付。
4. 更新器先备份当前安装，再启动安装目录外的替换程序。
5. FlowCast 正常停止分享并恢复路径后退出，替换程序等待文件锁释放。
6. 替换完成后只从新安装路径启动一次，并等待新进程写入健康标记。
7. 新版本未启动、版本号未改变或健康标记超时，自动恢复备份并启动旧版本。
8. 更新成功后清除备份；更新按钮在当前版本下不再显示。

## 12. 安装与运行边界

- 保持 WPF 自包含 Windows x64 发布。
- 用户下载和安装时只需要一个 Setup EXE。
- 安装目录可包含运行依赖；支持文件与 `router-helper` 应设为隐藏，而不是删除。
- 打包清单必须包含帮助程序版本和校验值。
- 单实例启动时，如果已有 FlowCast，第二个进程通知现有窗口恢复并前置，然后退出。
- 对卡死后残留的旧实例要区分“仍正常运行”与“失去响应”；不得通过结束无关进程解决。

## 13. 验证策略

### 13.1 单元测试

- 每个状态允许和禁止的转换。
- 快速重复选择、停止和切换只执行一次有效操作。
- 单选保证，取消确认不改变当前状态。
- 无声音信号仍允许开始分享。
- 没有选中程序时，B1 关闭不产生阻断提示。
- 已选程序不能取消选择或修改路径。
- 切换程序先恢复旧程序，再建立新路由。
- 静音不改变路径、选择或累计时长。
- 长设备列表被归纳为固定长度摘要。
- 人性化错误映射不泄漏技术代码。
- 更新成功、版本未改变、健康超时与回滚路径。

### 13.2 集成测试

- 使用假的路由执行器验证开始、停止、切换、回滚和过期回调。
- 验证只有被选程序进入分享端点；未选程序及分享期间新出现的程序进入 AUX，并在停止后全部恢复原路径。
- 使用真实 `router-helper` 子进程验证健康检查与协议，包含带 BOM 的标准输入。
- 验证当前程序确认结束后，B1 先关闭且待恢复日志保留；程序仍存活时，短暂无声或音频会话重建不会停止分享。
- 验证再次出现同一应用时，待恢复路径优先完成。
- 验证单实例第二次启动会唤醒已有窗口。
- 验证最小化后动画停止，但分享异常仍触发安全恢复。

### 13.3 UI 与打包测试

- 主窗口在最低支持尺寸下仍能看到状态、程序列表和停止动作。
- 超长程序名、设备名和多个端点不会改变窗口宽度。
- 所有 FlowCast 对话框无 Windows 默认黑色虚线焦点框；键盘焦点仍有符合设计的可见状态。
- 3 秒开屏期间主窗口不闪现，结尾 Logo 清晰，提示音只在本机播放。
- Release 构建后运行打包帮助程序协议测试。
- 静默安装后确认主目录只显式展示 `AudioShare.App.exe`，运行依赖仍存在且被隐藏。
- 从安装包启动、更新、回滚、卸载各执行一次实际验证。

### 13.4 实机音频验收

自动测试不能证明 Discord 对端真实听感。发布前必须在真实电脑上完成：

1. Chrome 或网易云在本机设备播放，选择后朋友能听到音乐。
2. 停止分享后朋友立即听不到，程序恢复到分享前设备。
3. 真人麦克风和音乐可同时进入 Discord，且朋友不会听到自己的回声。
4. 分享中关闭来源程序、拔除设备、关闭 Banana 和退出 FlowCast，朋友端均停止收到该程序声音。
5. 每次失败后重新打开 FlowCast，不会错误显示“正在分享”。

实机验收完成前，只能声明路由、打包和自动测试通过，不能声明 Discord 端到端分享已验证。

## 14. 完成标准

只有同时满足以下条件，本次大改才算完成：

- 主界面不再直接控制路由，所有分享操作经过 `ShareCoordinator`。
- UI 状态与实际程序路由、B1 读取一致。
- 一次只能分享一个程序，重复操作和切换没有竞争。
- 正常停止、程序结束、设备异常与退出都执行安全恢复，退出不会被恢复错误阻塞。
- 更新失败能够自动回滚，成功后确认启动新版本。
- 主界面、历史、自定义窗口和开屏通过最低尺寸与视觉检查。
- 单元、集成、打包测试全部通过。
- 实机 Discord 验收结果被单独记录，不以自动测试代替。
